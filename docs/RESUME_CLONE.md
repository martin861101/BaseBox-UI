# Update Summary: Services Tab & Resume Clone Engine

This document outlines the changes made to the MadScientist architecture to add the **Services** tab and the **Resume Clone Engine** — an AI-powered document generation workspace that tailors resumes to specific job specifications using the active agent's LLM provider, with styled PDF export.

---

## 📁 Files Created

* **`src/lib/resume-clone.ts`**
  * LLM orchestrator for the Resume Clone Engine. Contains the specialised system prompt that enforces authenticity constraints (no hallucinated history, verbatim job title matching, adaptive duty rephrasing, structure preservation). Streams results through the existing `/api/ai/chat` SSE backend endpoint using whichever agent is currently active. Also exports the `DEFAULT_RESUME_TEMPLATE` constant loaded from `document_services/RESUME_TEMPLATE.md`.

* **`src/lib/resume-pdf.ts`**
  * Client-side PDF generator. Parses the resume markdown into a professionally styled HTML document and opens the browser's print-to-PDF dialog. Styling includes:
    * Inter font family from Google Fonts
    * Blue accent header rule and bullet markers
    * Uppercase section headings with bottom borders
    * Bordered skills table with grey category column
    * A4 page size (`@page`) with 15mm/18mm margins
    * Print-safe layout with `break-after: avoid` on headings and `break-inside: avoid` on tables

* **`src/routes/_authenticated/services.tsx`**
  * Complete TanStack Router page containing three nested views managed via internal state:
    * **ServicesHub** — Dashboard grid of available AI service categories (Document Services is active; Agentic Workflows and Compliance Auditing are locked/coming soon).
    * **DocumentServices** — Sub-category picker with a card to launch the Resume Clone Engine.
    * **ResumeCloneEngine** — Split-panel workspace with:
      * **Left panel**: Editable Markdown textarea for the base resume template, a large text input for the target job specification, and a Generate/Stop button.
      * **Right panel**: Live-streaming Markdown preview of the generated resume with three export actions: Copy to Clipboard, Download `.md`, and Download styled PDF.

## 🏗️ Architecture Decisions

### Why not separate route files?
The blueprint in the original spec suggested separate component files (`ServicesHub.tsx`, `DocumentServices.tsx`, `ResumeCloneEngine.tsx`). The implementation consolidates all three views into a single route file (`services.tsx`) using internal state (`ServiceView`) to switch between them. This matches the existing codebase pattern (e.g., `ai-settings.tsx` manages multiple tabs in one file) and avoids unnecessary file fragmentation since the views are tightly coupled.

### Why stream through the backend?
The original spec called for a direct `fetch` to `localhost:11434` (Ollama). The implementation routes through the existing `/api/ai/chat` SSE endpoint instead. This means:
* It works with **any provider** (Ollama, OpenAI, Gemini, Claude, OpenRouter, Mistral, Hugging Face) — not just local Ollama.
* It uses whichever **agent** the user has selected, inheriting the correct API key, base URL, and model.
* The temperature is hardcoded to `0.2` for resume generation (low creativity = strict alignment), overriding the agent's default.

### PDF Generation Strategy
Rather than introducing a server-side PDF library (Puppeteer, wkhtmltopdf), the implementation uses a client-side approach:
1. The resume markdown is parsed into semantic HTML by a custom parser in `resume-pdf.ts`.
2. The HTML is wrapped in a self-contained document with embedded CSS (`@page` rules, Inter font, A4 layout).
3. A new browser window is opened and `window.print()` is triggered, allowing the user to "Save as PDF" via the browser's native print dialog.
4. This approach is zero-dependency, works in all modern browsers, and produces high-quality output.

### LLM System Prompt Constraints
The system prompt in `resume-clone.ts` enforces five critical rules:
1. **Exact Job Title — Verbatim Copy** — The output resume's title must be copied character-for-character from the job spec. This is marked as the #1 priority rule.
2. **Experiential Authenticity** — No fabricated companies, degrees, metrics, or career milestones.
3. **Adaptive Rephrasing** — Duties are reworded and reprioritised to mirror the job spec's language.
4. **Structure Preservation** — The output must match the input template's markdown structure exactly (header table, bold headings, bullets, skills table).
5. **Raw Output Only** — The LLM returns clean Markdown only, no conversational wrapper or code fences.

## 🚀 How to Use

1. Navigate to **Services** in the sidebar (or press `⌘K` and type "Services").
2. Click **Document Services** → **Resume Clone Engine**.
3. Edit the **Base Resume Template** (pre-loaded with your actual resume) or paste a different one.
4. Paste the full **Target Job Specification** including the job title.
5. Click **Generate Cloned Resume**.
6. Watch the output stream in real-time on the right panel.
7. Export your result:
   * **Copy** — copies raw markdown to clipboard
   * **⬇** — downloads as `Cloned_Resume.md`
   * **PDF** — opens a styled print preview for Save as PDF

> **Note**: The engine uses your currently active AI agent. Make sure one is configured in **AI Settings → Agents** with a working provider and model.
